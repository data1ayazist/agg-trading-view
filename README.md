# Кабинет market surveillance — прототип

Витрина **аномальных торговых сессий**: список сессий, отобранных автоматическими
критериями агрессивного воздействия на цену, с фильтрами и сортировкой.

Статический сайт: ни сборки, ни бэкенда, ни внешних CDN — годится для GitHub Pages
и открывается двойным кликом по `index.html`.

## Структура

```
index.html            разметка витрины и разбора сессии
assets/theme.css      дизайн-система: палитра, типографика, геометрия (только переменные)
assets/app.css        компоненты витрины
assets/data.js        данные выгрузки (автогенерируется, руками не править)
assets/tooltip.js     тултипы по data-tip
assets/app.js         фильтры, сортировка, рендер, роутер, состояние в hash
assets/universe.js    универсум клиентов, история 6 месяцев, индекс опасности, флаги
assets/session.js     разбор сессии: свечи, тепловые карты, новостной фон
assets/rating.js      рейтинг агрессивных трейдеров
assets/client.js      карточка клиента с визуализациями
tools/xlsx_to_data.py пересборка assets/data.js из Excel
anomal-sessions.xlsx  исходная тестовая выгрузка
```

## Экраны

| Маршрут | Экран |
|---|---|
| `#/anomal-sessions?...` | витрина аномальных сессий со списком и фильтрами |
| `#/session/<дата>/<режим>/<бумага>` | разбор одной сессии |
| `#/rating` | рейтинг агрессивных трейдеров между сессиями |
| `#/client/<код>` | карточка клиента: метрики за 30 дней и за 6 месяцев |

Строка витрины кликабельна (и открывается с клавиатуры по Enter). Возврат по
ссылке «← Витрина аномальных сессий» сохраняет фильтры, с которыми ушли.

## Обновить данные

```bash
python tools/xlsx_to_data.py
```

Скрипт читает `anomal-sessions.xlsx` (первый лист, шапка в первой строке, порядок
колонок как в исходном файле) и переписывает `assets/data.js`. Требуется `openpyxl`.

Инвариант выгрузки: **в сессии всегда сработал хотя бы один критерий**. Строка, где
все три флага `False`, — не аномалия; скрипт её не переносит в витрину и печатает
номер строки в лог.

## Публикация на GitHub Pages

1. Запушить репозиторий.
2. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.

Файл `.nojekyll` уже лежит в корне — Jekyll не трогает содержимое.
Все пути относительные, поэтому сайт работает и в подкаталоге `/<repo>/`.

## Что умеет витрина

- Список по убыванию даты; при равной дате выше идут сессии с бо́льшим числом
  сработавших критериев и бо́льшим модулем изменения цены.
- Фильтры: интервал дат, режим торгов, ценная бумага (поиск подстрокой,
  дебаунс 220 мс), уровень листинга. Режимы и уровни — мультивыбор.
- Сортировка по любой колонке кликом по заголовку.
- Объём торгов показан в **млн ₽** (в выгрузке — рубли), точное значение — в тултипе;
  в строке результата — суммарный объём отфильтрованной выборки.
- Состояние фильтров пишется в hash: ссылку вида
  `#/anomal-sessions?from=2026-08-05&board=TQBR&sort=closeChange:desc`
  можно переслать коллеге.
- Тултип с числовым значением на каждом элементе данных.

## Разбор сессии

Те же поля, что в строке витрины, плюс:

- **Минутные свечи** основной сессии (10:00–18:39, 520 свечей): зелёная — рост,
  красная — падение, пунктир — закрытие предыдущей сессии, вертикальная метка —
  аномальная минута. Под ценой — гистограмма минутного объёма. График
  прокручивается и открывается на аномальной минуте.
- **Три тепловые карты по часам** (08–22): «Покупки», «Тейкерские покупки»,
  «Продажи». По вертикали — коды клиентов вида `БКС_012345678`, по горизонтали —
  часы, в клетках — доля клиента в объёме этого часа. Сумма столбца ровно 100 %:
  показанные участники плюс строка «Прочие участники». Насыщенность клетки
  пропорциональна доле, число в клетке — целые проценты (от 5 %).
- **Продвинутые метрики агрессивных трейдеров** — таблица на 13 столбцов:
  код клиента, брокер, ИНН брокера, тип клиента (ЮЛ / ФЛ / нерезидент), доли
  покупок и тейкерских покупок по бумаге, их объёмы, доли покупок в длинных
  минутных свечах роста, число больших тейкерских заявок, число покрытых
  ценовых уровней и реализованная прибыль по FIFO. По 20 клиентов на страницу
  с пагинацией, сортировка кликом по любому заголовку (первый клик — по
  убыванию). Над таблицей — фильтры по типу клиента и по ИНН брокера, а также
  скрытая плашка «Перенастроить сортировку»: столбцам 5–13 задаются веса от 0
  до 1 (по умолчанию 1), метрики нормируются по видимой выборке и складываются
  в индекс агрессивности, по которому список отсортирован по умолчанию.
  Пересчёт — по дебаунсу 220 мс.
- **Новостной фон по эмитенту** — четыре корпоративных события за десять дней до
  сессии, каждое из своей категории: отчётность и финрезультаты, смена
  менеджмента, сделки M&A, решения по капиталу, операционные показатели.
  Для ETF и БПИФ роль эмитента играет управляющая компания.
- Справа — `Полная тепловая карта`, `Momentum Ignition-анализ`, `Spoofing-анализ`:
  пока заглушки.

## Рейтинг агрессивных трейдеров

Отвечает на вопрос «кого расследовать первым» между сессиями. Два окна:
**30 дней** и **6 месяцев**, переключаются одним кликом.

### Методология индекса опасности

1. За выбранное окно по каждому клиенту считаются восемь метрик: тейкерский
   объём покупок · доля тейкерских покупок в длинных свечах роста · участия
   в аномальных сессиях · большие тейкерские заявки · среднее число ценовых
   уровней, снятых за сессию · доля активности в открытии и закрытии ·
   повторяемость (активных дней × бумаг) · реализованная прибыль FIFO.
2. Каждая метрика переводится в **перцентильный ранг** внутри окна, а не
   нормируется min-max: один клиент-выброс не должен схлопывать шкалу
   остальным, а «выше 97 % рейтинга» читается без пояснений.
3. Индекс = взвешенная сумма рангов × 100. Веса 0–1 задаются в скрытой плашке
   «Перенастроить индекс», по умолчанию все равны 1, пересчёт по дебаунсу 220 мс.
4. **Порог допуска**: в рейтинг попадают клиенты с тейкерским объёмом от 1 млн ₽
   (за полгода порог кратно выше) и минимум тремя активными днями. Без порога
   клиент с единственной удачной сделкой в рывке получил бы 100-й перцентиль
   по доле покупок в рывках. Сколько клиентов отсечено — видно в тултипе
   строки результата.
5. **Объяснимость**: столбец «Почему» показывает две метрики с наибольшим
   вкладом в индекс, а столбец «Индекс за другое окно» со стрелкой — клиент
   разгоняется или затухает. Стабильно высокий фон и свежий всплеск требуют
   разной очерёдности разбора.

Фильтры: окно, тип клиента, ИНН брокера, флаг расследования. По 20 клиентов
на страницу, сортировка кликом по любому столбцу.

### Карточка клиента

Открывается кликом по строке рейтинга (и по строке таблицы метрик в разборе
сессии — это тот же человек):

- индекс и место за оба окна, вердикт «разгоняется / затухает / устойчив»;
- разложение индекса: вклад каждой метрики с перцентилем и весом;
- помесячная динамика: столбцы объёмов и линия индекса за 6 месяцев;
- таблица метрик за 30 дней и за 6 месяцев со значениями и перцентилями;
- кольцо распределения тейкерского объёма по бумагам;
- эпизоды в аномальных сессиях с переходом в разбор конкретной сессии.

### Флаг «отправлен на расследование»

Ставится кнопкой в рейтинге или на карточке клиента, фильтруется в рейтинге
тремя состояниями: все / отправленные / не отправленные.

В продукте статус хранится в **БД надзорной системы** — он общий для всех
сотрудников. В прототипе сервера нет (GitHub Pages отдаёт только статику),
поэтому весь доступ к статусу собран в одном объекте `flags` в
`assets/universe.js` поверх `localStorage`. При подключении бэкенда меняются
только его методы `has / get / count / toggle` — на `GET` и `POST` к API,
остальной код не трогается.

### Откуда берутся данные разбора

В выгрузке нет микроструктуры, поэтому свечи, доли участников и новости
**синтезируются в браузере** (`assets/session.js`) — это демо-данные прототипа,
а не реальные сделки. Генерация детерминирована: сид считается от пары
«дата + бумага», поэтому сессия всегда выглядит одинаково и ссылку можно
переслать. Синтетика согласована с выгрузкой:

- последняя свеча даёт ровно то изменение цены закрытия, что в таблице;
- аномальная минута даёт ровно тот максимальный прирост, и ни одна другая
  минута его не превышает;
- при флаге `marking the open/close` аномальная минута ставится в первые или
  последние минуты сессии;
- объём торгов из выгрузки разносится по часам 08–22 (час аномалии тяжелее) и
  далее по минутам основной сессии; сумма по часам сходится с выгрузкой до рубля,
  а доля клиента в покупках или продажах переводится в рубли через оборот часа;
- в час аномалии в картах «Покупки» и «Тейкерские покупки» один участник
  заметно выделяется — чтобы на прототипе было видно, как выглядит агрессор;
  он же подсвечен в таблице метрик и по умолчанию стоит первым;
- объёмы в таблице метрик берутся из тех же тепловых карт: у восьми участников
  карт — из их долей по часам, у остальных — из строки «Прочие участники».
  Поэтому сумма покупок по всем клиентам равна объёму торгов из выгрузки.
